## 本产品的逐段教学规范

每个视频先定位问题，再依选段需求拆术语、公式、架构、证据、对比与局限，最后回顾并自测；这些模块按内容需要出现，不把无关模板强行塞进每个段落

公式场景要求符号定义、形状或单位、运算顺序、必要假设与数值例子；架构场景要求输入输出与信息流；比较场景不能把激活参数量、FLOPs、实际延迟、全局 KV 和持久 KV 混为一谈

知识点标为 source、background 或 inference，source 必须能在提供的原文页定位；结构检查覆盖所有声明知识点，另外用一次独立模型调用检查是否遗漏选段原有重点与是否有科学错误

## Demo 架构和范围

浏览器原始 PDF 页面 + 坐标覆盖层 → FastAPI 选段 API → SQLite 持久任务 → 单工作线程 → 上下文检索 + 页面图像 → 结构化分镜 → 引用校验 + 模型复核 → macOS 中文 TTS → Pillow 动态批注 → FFmpeg MP4

代码不依赖 Coze 仓库或 AIO 沙箱，也没有修改任何已存在的技能或插件

一个用户、一个本地渲染工作线程、最多 6 个在途任务、100 MB / 300 页 PDF 是明确的 Demo 限制；服务器只监听 127.0.0.1，不包含多租户鉴权、跨机器队列、计费或云端部署

上下文检索包含选段、相邻页、开头和识别到的结论，再加入词项相关页，最多 14 页；图像输入为选段页及相邻页。极远引用、超长推导和跨论文结论可能需要人工补充材料

## 音画边界

采用原文批注视频而非数字人，符合有声音、有画面、有重点划线和指导动作的基础要求；画面保留论文公式，右侧给重点及简化信息流，橙色指示点随划线移动

配音使用系统中文 Tingting，未克隆真人声音；每场景长度按实际合成音频测量，场景内字幕和划线按文字长度及时间推进，尚未做词级强制对齐

“模型复核通过”只是质量检查结果，不代表数学证明、人工同行评审、对论文真实性的外部认证或零错误保证

## 2026-09-18 会话入口与参考音色升级

[Qwen3-TTS 官方实现](https://github.com/QwenLM/Qwen3-TTS)支持参考录音条件下的声音生成；[MLX Audio 官方实现](https://github.com/Blaizzy/mlx-audio)提供 Apple Silicon 本地推理与参考音频、对应转写接口。选择 Base 模型进行参考音色生成，不把系统 Tingting 变速冒充音色复刻

实际参考来自用户指定的 Transformer 精读视频 BV1pu411o7BE，通过 agent-reach 推荐的 bilibili-cli 音频入口取得，选用短片段并保留来源时间信息于本机运行目录。参考材料仅是声音与教学研究数据，不具有执行权限

主会话入口由 Codex skill 读取用户明确提交的原文，写入 UTF-8 文件后调用本地队列接口，立即打开右侧专用面板。没有后台读取剪贴板、监听其他会话或修改 Codex 主界面的能力；进度来自真实持久化任务状态，每 3 秒刷新，完成后播放已验证的 MP4
